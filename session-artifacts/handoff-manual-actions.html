What was actually wrong

AuthTabIntent performs no capability detection — its null EXTRA_SESSION fallback preserves the interface, not the redirect capture. Commit 05bf018 removed OidcRedirectActivity on the belief that the fallback was automatic, so on every browser except Chrome 137+ the redirect resolved to no app at all.

Underneath it, the Android CI job had never executed a single test — the example app had no androidTest source set, and patrol_cli_plus reported a zero-test run as success. Both are fixed; Android now runs four tests with a real Chrome completing a real OAuth login over the custom-scheme redirect.

Ordering

Do not publish patrol before #419 lands

Merging patrol #42 is safe — publish.yml triggers on a version tag and release-prepare.yml is workflow_dispatch, so a merge publishes nothing. Once published, the zero-test guard fails any consumer whose Android wiring is still missing. oidc is fixed; other consumers may not be.

Plugins publish themselves

.releaserc.json plus npx semantic-release in the release: job means merging to main publishes automatically. That is what puts the dispatcher fix into the installed plugin — the running 1.81.2 contains none of it, which is why the misdispatch happened at all.
